# Alibaba Product Draft

Turn a folder of product photos into `output/product-draft.json` for the Edge fill/upload panel. This skill stops before any page mutation.

## Inputs

- Product images in `产品/` by default, or a directory passed to the scripts with `--input`.
- Optional reference listing data supplied by the user.
- Company values come from the plugin configuration, never from the model.

Supported inputs: `.avif`, `.webp`, `.jpg`, `.jpeg`, `.png`.

## Outputs

- `images/*.png`: normalized images for the gallery and upload.
- `output/image-manifest.json`: conversion metadata.
- `output/vision.json`: facts visible in the images.
- `output/listing.json`: English title, keywords, description, attributes, defaults, and gaps.
- `output/product-draft.json`: the file consumed by the Edge panel.
- `output/product-draft.md`: human review copy.
- `output/page-field-map.json`, `output/description-preview.html`: supporting artifacts.

## Workflow

1. Prepare images:

   ```powershell
   node <skill-dir>/scripts/prepare-images.js --root .
   ```

   If `sharp` is missing, install it once with `npm install sharp` in the project root.

2. Choose at most three images for visual analysis: main view, detail/exploded view, and specification/engineering drawing. Do not inspect every gallery image.
3. Inspect those images once, then write `output/vision.json` using [references/vision-schema.md](references/vision-schema.md). Record only visible facts; put everything else in `not_visible_in_images`.
4. Write `output/listing.json` using [references/listing-schema.md](references/listing-schema.md). This is the only file the builder needs for copy and attributes.
5. Build the draft:

   ```powershell
   node <skill-dir>/scripts/build-draft.js --root .
   ```

6. Validate:

   ```powershell
   node <skill-dir>/scripts/validate-draft.js --root .
   ```

7. Report only the output paths, title length, image count, and the `missing` list. Do not paste the full description or draft into chat.

## Non-negotiables

- One visual pass per product. No per-field model calls.
- Do not send full page HTML to a model.
- Do not invent dimensions, materials, certifications, cable compatibility, impedance, frequency, VSWR, MOQ, price, lead time, packaging size/weight, or company data.
- Unknown or business-sensitive values belong in `missing`, with a concrete action.
- Company fields keep the placeholders `{{company.brand}}`, `{{company.origin}}`, `{{company.manufacturer_batch}}`, and `{{company.name}}`. The Edge panel resolves them.
- Company description and company FAQs are not generated by the model; they come from the plugin configuration.
- Do not upload images, fill the Alibaba page, save, or publish. That is the panel's job.
- Reuse existing `output/vision.json` or `output/listing.json` when the images and user inputs have not changed.

## Token discipline

- Inspect at most three images.
- Write compact JSON with no prose values beyond the defined fields.
- Prefer one combined `listing.json` over separate per-field calls.
- Keep the final chat response short; the artifacts carry the detail.
